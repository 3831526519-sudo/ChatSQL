# ChatSQL 教育模式改进方案与执行清单

## 1. 问题与目标

现有左侧面板只是「意图、返回列、最多几行」的摘要，不能帮助用户读懂 SQL。更严重的是前端会用自己的简化摘要覆盖后端子句解释，缺少统一教学数据与源码定位。

本次目标：用户能够针对正在编辑的真实 SQL，理解语句由什么组成、为什么使用这些关键词/函数/符号、语句书写与逻辑处理顺序为什么不同、替换写法会改变什么，以及结果不能说明什么。界面和教学使用中文，SQL 标识符保留原文。

非目标：本次不添加自动执行、提交答案/评分、DDL 教学执行、数据库写入、任意复杂 SQL 支持，不把语法解释视为意图正确性或性能评估证明。

## 2. 教学原则

1. AST 是结构事实来源。引用实际 SQL 片段，不用关键词正则猜整条查询结构。
2. 源码词法扫描只用于定位 AST 已确认的顶层子句，以及识别符号范围；引号、注释、括号内的关键词不能冒充子句。
3. 程序提供可验证的语法解释；原查询计划的意图、筛选值来源可补充上下文，但模型草稿不等于数据库事实。本次不新增自由生成教程的模型请求。
4. 出现什么就讲什么，不为没有使用的 JOIN/GROUP BY/函数强行填充卡片。对比示例可出现其他写法，但必须明确是教学对比。
5. 不把样例数据、估计结果或模板示例冒充真实查询结果；不执行教学示例。
6. 修改 SQL 或参数后，旧讲解立即标记失效并移除定位；关闭模式后隐藏/移除全部教程。
7. 开关学习、定位子句、展开对比均不触发数据查询，不消耗执行确认，也不追加云模型调用。

## 3. 教学内容模型

### 3.1 概览

- SQL 原文、方言 MySQL、讲解版本、状态（supported/unsupported）、源码指纹。
- 原查询计划存在且与该 SQL/参数快照一致时显示意图；手写 SQL 无可靠业务意图时只描述结构，不能猜业务目的。
- 原始 SQL 与参数分别保留，值不能拼接进可执行 SQL。

### 3.2 每个实际子句的卡片

统一字段：`id / title / sql / range(start,end) / what / why / details[] / pitfalls[] / comparison`。

- **SELECT**：实际输出字段与表达式；逗号分隔；字段名与关键词的区别；为什么显式列清单；AS 是本次结果的别名，不改表结构。
- **DISTINCT**：属于 SELECT 的去重修饰；对完整输出行/列组合去重；不保证排序，不是只对第一列去重。
- **FROM / JOIN**：真实来源、别名、限定列名；有 JOIN 时根据实际连接类型解释保留哪些行与 ON 的作用；无外键证据不能把同名字段说成真实外键关系。逗号多表/交叉连接说明笛卡尔积风险。
- **WHERE**：筛选原始行；具体列、操作符、参数值；AND/OR 与括号、NOT 的作用；先筛行再做分组。
- **GROUP BY**：按实际字段分组；非聚合输出与分组键的关系；分组不保证排序。
- **HAVING**：筛选分组/聚合后的结果，与 WHERE 的阶段不同；不声称所有数据库/查询都必须含 GROUP BY 才能使用 HAVING。
- **ORDER BY**：列或输出别名、ASC/DESC；多排序键按先后决胜；相同键无唯一决胜条件时顺序可能不稳定；排序方向影响 LIMIT 截取哪一段。
- **LIMIT**：实际上限、如有 OFFSET 的概念；系统默认安全上限与用户要求必须区分；不等于表总行数，也不保证所有匹配记录均已返回。

### 3.3 两种顺序

显示实际出现子句的书写顺序，而不是把未用子句塞进本次语句。

- 常见书写顺序：SELECT → FROM/JOIN → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT。
- 教学逻辑顺序：FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT。
- 明确：这是帮助理解的逻辑模型，不是数据库物理执行计划；优化器可能重排、合并步骤。别名可用位置也有 MySQL 特例，不用简化顺序做绝对断言。

### 3.4 函数、表达式与符号

只详细解释当前语句实际出现的项：

- COUNT(*) 统计行；COUNT(column) 忽略该列的 NULL；COUNT(DISTINCT column) 统计不同的非 NULL 值。
- SUM/AVG/MIN/MAX 的用途与 NULL/空集合含义；COUNT 空集合为 0，其他常见聚合通常为 NULL。分组不存在则不会凭空输出每组。
- LOWER/UPPER/LENGTH、COALESCE、ROUND/ABS、YEAR/MONTH/DAY/DATEDIFF，逐一绑定实际函数调用，区分函数与字段名。LENGTH 是字节数，不保证是字符数。
- `SELECT *` 是所有列；`COUNT(*)` 中星号是统计行语义，不是 LIKE 通配符，也不是乘法。乘号仅在乘法表达式时解释。
- LIKE 的 `%` 匹配零个或多个字符，`_` 匹配一个字符；只在 LIKE 模式上下文解释它们，不把普通字符串或 SQL 取模符误叫通配符。转义符与排序规则可能影响匹配，不能保证大小写敏感。
- `?` 显示参数序号、真实绑定值、用途及安全理由；不把问号当存储值，不显示凭据。
- `NULL` 与 IS NULL/IS NOT NULL；`= NULL` 不能用来检查空值。指出 SQL 的未知值逻辑，不能等同于空字符串/0。
- AS、逗号、括号、反引号、分号、限定字段的点号，按实际出现与语义解释。引号内同名关键词不能被误识别。

## 4. 对比与常见误区

每个子句可展开「深入理解」「对比写法」「常见误区」，默认只显示片段、作用和本次理由。

- DISTINCT：去掉后可能出现重复输出行；不能虚构具体重复数量。
- COUNT：统计行和统计某列非空值的区别；不暗示当前真实数据存在 NULL。
- LIKE 与等号：模糊匹配与精确比较的区别。
- WHERE 与 HAVING：筛行和筛组的区别。
- SELECT 显式列与 *：列数/可读性/数据暴露边界；不断言某一种写法一定更快。
- LIMIT/ORDER BY：无排序不保证稳定；去掉 LIMIT 可能返回更多行，但不保证本次就更多。

对比示例是静态文本，没有运行按钮、自动替换编辑器或自动执行行为。

## 5. 交互与可访问性

1. 学习模式开启时保留左侧讲解、右侧编辑/结果的布局，桌面面板适当加宽，移动端上下排列。
2. 顶部目录导航至「语句结构」「两种顺序」「函数与符号」「注意事项」。
3. 点击卡片中的「定位代码」选择并滚动到编辑器对应片段；保留输入内容，不触发 input，不使执行快照失效。
4. 用户点击或键盘移动编辑器光标，左侧对应子句卡片高亮，不抢走编辑器焦点，不反复强制滚动。
5. 折叠项用原生 details/summary，定位用真实 button；支持键盘，范围用 aria-current 表示。
6. 老讲解与 SQL 不一致时不允许旧范围继续定位；异步返回落后于编辑版本时丢弃，防止讲解串台。
7. 关闭模式可立即清除教程，不能只把过时内容留在可访问性树中。

## 6. 模块与 API 边界

- `src/sql/learning.mjs`：纯教学引擎；输入 SQL、参数、可选可信语义计划，输出结构化教育文档。无 DB、网络和模型调用，无执行权限。
- `POST /api/learning/explain`：生成纯结构讲解，不执行 SQL，不读取业务记录；可带 queryId，只有其 SQL/参数仍匹配存储快照时才带原业务意图。queryId 查阅不得消费确认令牌。
- 生成/预览接口：学习开启时返回 `education`，关闭时为 null；保留现有 `learning` 兼容字段供旧测试/调用方迁移，但前端优先渲染新结构，不能再用简化摘要覆盖它。
- `Approvals.peek`：只读快照查阅，仍遵守过期，返回拷贝。
- 前端：教育渲染、缓存与联动；相同 SQL/参数可复用匹配的教育文档，不等同于延长执行令牌有效期。教育缓存与执行授权严格分开。
- 内置模板负责语法；未来若增加模型补充须显式标注可选建议，不覆盖 AST 事实，本次不依赖它。

## 7. 支持边界与错误处理

本版教育引擎支持普通单条 SELECT、常用聚合/函数、WHERE/GROUP BY/HAVING/ORDER BY/LIMIT 和可解析的普通 JOIN。未实现的复杂 CTE、UNION、子查询、窗口或方言扩展明确提示不支持完整讲解，不生成看似准确的残缺教程。

手写 `SELECT *` 或字符串字面值可做纯结构讲解，但不因此放宽执行策略；讲解成功不代表查询被允许执行、字段真实存在或获得数据库权限。未知函数只说明识别到调用且本版没有内置说明，不能捏造作用。

## 8. 测试与验收标准

| 编号 | 验收项 | 通过条件 |
|---|---|---|
| E01 | SELECT/FROM/LIMIT | 演员两列示例展示真实片段、字段角色、理由、上限、分号与无排序警告 |
| E02 | 顺序 | 书写顺序和逻辑顺序分开，并声明不是物理执行计划 |
| E03 | DISTINCT | 对完整返回行去重，不声称排序或只去第一列重 |
| E04 | 聚合 | COUNT(*)/COUNT(col)/COUNT(DISTINCT col) 不混淆；SUM/AVG 等说明空值 |
| E05 | LIKE | %/_ 仅按模式语义解释，实际参数值可见 |
| E06 | 条件/空值 | AND/OR 优先级、括号、IS NULL 与 = NULL 边界正确 |
| E07 | 标识符与定位 | 反引号或字符串里的 FROM/WHERE 不产生假子句，范围精确对应原 SQL |
| E08 | UI 联动 | 点击定位、编辑器光标联动、折叠、关闭和编辑失效有 DOM 测试 |
| E09 | 不执行 | 解释 API、开关与定位没有数据查询/模型调用，不消费确认令牌 |
| E10 | 兼容 | 保留生成、手工 SQL、确认执行与结果流程；改变学习开关不重写 SQL |
| E11 | 退化 | 不支持/解析失败有中文提示，不假装完整解释 |
| E12 | 安全 | SQL/参数等用 textContent 渲染，不能把数据内容当 HTML 执行 |

真实云端/数据库业务验收与本次纯教学功能验收分开，自动测试通过不代表完整 Agent 已在真实库上验收。
