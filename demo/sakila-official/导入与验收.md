# 官方 Sakila 示例库：导入与验收

## 来源与当前状态

- [MySQL 官方安装说明](https://dev.mysql.com/doc/sakila/en/sakila-installation.html)
- [官方 ZIP 下载地址](https://downloads.mysql.com/docs/sakila-db.zip)
- 已下载原始 ZIP 并检查其文件清单，已解压官方 SQL，没有改写其中的数据。
- 本地 ZIP SHA-256：`ef4ab9aab7a433311eff6558561bf47de231fe9f6d49f03de67e593418df719c`。这是本地文件指纹，不是额外的官方签名验证。
- 尚未执行任何建库或导入脚本，也未验证本机 Sakila 记录数。

## 重要风险

[官方建表脚本](sakila-db/sakila-schema.sql)包含 `DROP SCHEMA IF EXISTS sakila`，会删除已有 sakila 数据库后重建，不能对需要保留的同名库执行。它还创建视图、触发器、函数和存储过程。

保留原来的 menagerie，不需要删除它。此次导入是由你在 Workbench 明确执行的安装操作，不是给查询 Agent 开启写入/结构变更权限。Agent 后续仍应只读。

## 在 Workbench 操作

1. 打开本机 MySQL 连接。确认没有需要保留的 sakila 数据库；如已有同名库，先停止，另行设计新库名，不要直接执行。
2. 菜单 File → Open SQL Script，打开 [sakila-schema.sql](sakila-db/sakila-schema.sql)，阅读开头的删库/建库操作；确认目标是本机测试环境后再用闪电按钮执行整个脚本。
3. 确认建表阶段没有红色错误后，再通过相同菜单打开 [sakila-data.sql](sakila-db/sakila-data.sql)，执行整个脚本，等待完成。不要使用 CSV 导入向导，不要转换格式。
4. 若任何阶段有错误，先保存错误文字并停止后续操作；不要仅凭左侧出现表名判断成功。
5. 在 Schemas 刷新，应出现 sakila。此时先验收数据，再把 ChatSQL 的默认数据库切换到 sakila。

## 必须先核对的数据

MySQL 官方安装说明列出的基准为 film 和 film_text 各 1000 条。下面两个只读查询分别执行，每条最多返回 1 行；若由 Agent 执行，需先展示并取得明确确认。

```sql
SELECT COUNT(*) AS film_count
FROM sakila.film
LIMIT 1;
```

```sql
SELECT COUNT(*) AS film_text_count
FROM sakila.film_text
LIMIT 1;
```

只有两项都是 1000，且导入未报错，才继续检查其他表和业务查询；这仍不等于所有表已全面验收。

## ChatSQL 测试顺序

1. 在连接配置中选择默认数据库 sakila，并授权所需表；只读使用。
2. 先测试单表任务，例如列出电影名称、列出不同电影分类。
3. 核对显示的字段、绑定参数、行数上限及实际结果，再观察中文讲解。
4. 当前自然语言计划编译器不支持 JOIN，不要把多表关联题当作首轮通过标准。多表能力应后续单独实现并验收。
5. 保留一组人工核对的基准查询，用其实际结果对照 Agent，而不是只看是否生成了 SQL。
