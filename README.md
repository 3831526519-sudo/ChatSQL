# ChatSQL

单人使用的自然语言 MySQL Agent。项目借鉴 `dsh-mysql` 的连接器做法，但独立实现产品界面、Agent 编排、执行确认与 SQL 教学功能。

## 产品边界

- MySQL 优先；首版面向本机、单用户使用。
- 数据库连接由后端管理，凭据不得进入模型提示词、浏览器日志或聊天记录。
- 默认只读，只访问用户明确选择并授权的数据库/表。
- Agent 先读取授权 Schema，再生成单条只读 `SELECT`；使用参数绑定、显式列清单、默认 `LIMIT 100`，硬上限 `1000`。
- 执行前展示 SQL、参数语义与行数上限，等待用户明确确认；未确认绝不执行。
- SQL Learning 开启时分段解释查询意图、表/连接、筛选与聚合等子句、结果含义；关闭时只给 SQL 和结果。
- 云端模型通过可替换的 Provider Adapter 接入。

## 借鉴 dsh-mysql 的连接方式

1. 后端集中保存连接配置并安全处理凭据，不让浏览器持有密码。
2. 按连接惰性创建、复用连接池；连接设置变化时回收旧池。
3. 用 MySQL `information_schema` 读取用户授权的表、列、类型、可空性、键与注释。
4. 为每个会话明确绑定数据源和授权范围；每次调用只路由到该数据源。
5. 连接器仅负责测试连接、Schema 元数据和受控查询执行；自然语言生成、确认 UI、教育解释属于 ChatSQL 自己的层。

## 模块与边界

- `apps/web`：聊天界面、数据源设置、Schema 浏览、SQL 预览/确认、结果表、学习模式开关。
- `apps/api`：连接服务、Schema 服务、Agent 编排、只读 SQL 校验/执行、Provider Adapter。
- `packages/mysql-connector`：MySQL 驱动适配、连接池、连接测试、元数据读取；不负责生成 SQL 或教学。
- `packages/sql-policy`：语句分类、单语句校验、参数校验、授权表范围、LIMIT 与超时策略。
- `packages/learning`：结构化解释内容；学习模式关闭时不向 UI 输出教程。

自然语言模型只提出结构化查询意图，不直接提供可执行 SQL。服务端编译计划并强制字段、证据、权限、LIMIT 和参数绑定，再通过独立的一次模型调用核对用户意图。模型复核仍可能出错，数据库权限与程序校验不可替代。手工 SQL 是明确标记的独立入口，不冒充已复核的自然语言查询。

## 核心流程

连接与范围授权 → 读取真实 Schema → 模型提出结构化意图 → 校验字段、需求片段和取值来源 → 若缺证据，生成有界探查 SQL 并等待确认 → 把已确认样例作为证据 → 程序编译参数化 SQL → 另一次模型调用审查意图 → 展示统一查询计划/参数/上限 → 用户确认 → 消费同一不可变快照并只读执行 → 展示结果。

## 首版测试与验收

- 连接：正确/错误凭据、不可达主机、超时；密码不出现在 API 响应或日志。
- Schema：仅返回获准数据库/表的元数据；空授权、无默认库和未知列均安全失败或明确澄清。
- SQL 安全：拒绝 DML/DDL、多语句、未授权表、无界结果；所有值参数化；LIMIT 不超过 1000。
- 确认：确认前执行次数为零；拒绝/取消不执行；只执行已展示且未被修改的 SQL。
- 教学：开启时解释意图、表/连接、关键子句和结果；关闭时只显示 SQL 与结果。
- Provider：替换模型 Provider 不改变连接器和安全执行接口。

## 整库范围与记录上下文

- 配置可选择授权默认数据库全部表（包含新增表），不必逐表填写。仅限指定数据库，不扩展到服务器上其他库，保持只读与 SQL 校验。
- 数据库访问和云模型数据发送分别授权；开启任一扩展授权都必须明确接受风险。整库授权不代表立即扫描/上传所有记录，也不取消具体 SQL 的执行前确认。
- 只有成功执行且已确认的查询结果可加入记录上下文；未执行的候选 SQL 不会产生数据证据。按连接隔离，最多保存最近 4 份样例，每份最多 100 行、20 列、约 12000 字符，字符串截断至 256 字，15 分钟过期；删除连接同步清除。
- 常见敏感列名会被排除，但别名、自由文本等可能仍含隐私，不能宣称彻底脱敏。必须由用户确认数据范围适合发送到选定服务商。
- 辅助查询执行后，前端可基于当前未改变的问题自动继续生成最终查询；绝不自动执行最终查询。重复相同辅助 SQL 会停止继续取样并澄清，避免循环。关闭记录授权不发送任何样例。
- 当前新增整库/记录功能已通过模拟测试，尚未在用户真实数据库与云模型上进行端到端验证。
- 运行版本核验：新后端 `/api/health` 返回 `apiVersion: intent-plan-v1` 与记录能力标志；前端拒绝把旧后端视为已升级，也会阻止向旧进程保存新授权配置。实际排查曾确认现有 4317 服务仍只返回旧健康响应与不含新授权字段的连接对象；代码修改不会自动替换该 Node 进程。
- 不再从追问文字猜表名/字段名，也不随机选择首张表。数据值探查必须带结构化表/字段引用；缺少筛选值证据由编译器抛出明确的取值要求。真正业务歧义保留澄清，不替换成无关取样。

## 结构化查询计划（本次核心改造）

- [计划编译器](src/sql/plan.mjs)：单表返回项、AND 筛选、IN/空值、排序、去重、COUNT/SUM/AVG/MIN/MAX 与分组。模型输出不含 SQL；SQL 仅由程序依据已授权标识符生成。暂不支持自然语言 JOIN、OR、日期运算或子查询，不能悄悄简化这些需求。
- 每个返回项、筛选和排序项必须给出来自原问题的逐字需求片段。参数来源分为用户明确值或已读取字段值；观察值必须在该连接、该表、该列的样例中真实存在。数值类型、重复输出名、无效分组、任意额外条件和超限请求均检查。
- 需求片段匹配和样例存在性只提供可审计依据，不证明模型理解一定正确。另一次模型调用核对是否遗漏、添加或误解条件；复核拒绝或格式无效时不创建执行快照。同一模型二次审查不是形式化语义证明。
- [证据上下文](src/model/records.mjs)只将单表直接列视作原始字段值；计算表达式伪装的列、被截断的值不能作为等值映射依据。样例缺失不是值不存在，未解释的数字代码不是业务含义。
- [Agent 编排](src/model/agent.mjs)输出阶段轨迹：结构加载、意图规划、证据需求、计划编译、语义复核、等待确认。生成层没有调用数据查询执行器的路径。
- 界面展示表、返回项、筛选值、值来源、行数和复核状态；绑定参数始终可见。学习讲解围绕同一计划生成。运行未改动的生成结果时直接确认其原始快照，不通过手工 SQL 预览丢掉语义信息。
- 修改 SQL/参数使旧快照和复核失效；修改后的运行明确标为手工 SQL，仅有结构/安全校验。复核过的计划过期后也不能假装仍有效。
- 已验证：101 项离线/模拟 HTTP/DOM 测试通过，包括不同实际编码、无证据、虚构字段、语义复核否决、敏感/截断/表达式证据、快照一致性和可见参数。
- 待验收：真实云模型 + 用户 MySQL 的完整问答与结果对照。没有擅自建立测试库或写入数据；真实读取前仍须列出 SQL 并取得确认。

## 本机运行与验收

在项目目录执行 `npm.cmd start`（Windows PowerShell），保持窗口开启后访问 `http://127.0.0.1:4317/`。后端有改动时先按 Ctrl+C，再重新启动；连接只留在进程内存，重启后须重新添加。诊断页在 `/test`。

首页为配置视图；数据库连接（含授权表）与模型配置就绪后，“进入查询工作台”按钮才启用，不自动跳转。点击入口时会重新检查服务端状态；工作台与配置表单不同时显示，可用“返回配置”切换。返回配置会撤销尚未执行的预览，保留本页的问题内容。模型已配置不等于云端调用已验证。已在本机现有服务页面确认配置视图与入口禁用状态。

添加授权数据源后查看表结构，配置模型并点击“进入查询工作台”。新版采用 SQL 编辑器工作模式：顶部自然语言输入框右侧箭头负责生成 SQL，只填入编辑器，不运行。编辑器支持直接修改 SQL、显示行号、编辑 JSON 参数及恢复最近一次生成内容。点击“运行 SQL”后先弹出最终 SQL/参数/LIMIT 确认框；点击“确认运行”才执行，结果显示在下方“查询结果”标签。取消或按 Esc 不执行。

“查询结果”右侧的表名标签来自当前数据源的真实授权 Schema，默认展示字段结构；可将显式列清单的表查询载入编辑器，再经运行确认读取记录，不自动读取表内数据。支持鼠标和左右方向键切换标签。

开启“学习模式”时，左侧展开中文讲解面板，编辑器与结果区域右移；窄屏改为上下布局。未改动的结构化计划可复用匹配的教育文档，保留原执行快照；手工 SQL 或首次开启学习时，通过只解析 SQL 的 /api/learning/explain 补充完整结构讲解，不读取数据库元数据/业务记录、不调用模型、不消费确认令牌。关闭学习模式会移除教学内容；编辑代码使旧讲解失效。无“提交答案”按钮。本版问题独立处理，未实现多轮上下文或提问记录持久化。

已在现有本机页面临时展开空白工作台，检查了桌面尺寸下左侧讲解/右侧编辑结果的相对位置，无水平溢出；仅为布局检查，未调用模型或执行 SQL，之后已恢复正常配置入口。

模型设置：填写服务商的 API Base URL（不含 `/chat/completions`）、模型名与 API Key；只支持兼容 Chat Completions 和 JSON response_format 的服务。保存配置只校验格式，不代表云端连接成功；首次提问才会调用模型。密钥只在本机密码框输入，不要发进聊天。

自动测试：`npm.cmd test`。测试使用临时端口和模拟模型，不访问真实 MySQL、云端 API 或插件凭据。当前开发环境 Node.js 24。
